Reach out right now and press an imaginary light switch. Before your finger even touches it, some part of you already expects the room to brighten. You did not have to flip it to know — you *predicted* the outcome. That small, silent prediction, running quietly ahead of your actions all day long, is the idea at the heart of our third and most advanced project. It has a name, **world model**, and this chapter is about what it is and why an agent working in a computer would love to have one.

We are stepping up from fixing single functions to something bigger: an agent that solves whole tasks by typing commands, over many steps, into a computer. The new idea we add to it is not a faster algorithm or a bigger model. It is a hunch — a built-in sense of what will happen next.

## The little simulator in your head

You use predictions like the light-switch one constantly, without noticing. Before you push a door, you already expect it to swing away from you. Before you pour a full glass, you expect it to fill. A chess player, hand hovering over a piece, pictures the whole board *after* the move — not one move but a fan of possible futures — and picks the one they like. In each case there is a tiny simulator running inside the mind, taking the current situation plus a possible action and answering: *and then what?*

A dashed takeaway box in black at the bottom: "you predict the outcome BEFORE you act — that prediction is a world model". || A world model is the everyday habit of predicting what will happen next, before you do the thing. You already own several.]]

That is exactly what we mean by the term. A **world model** is a model's built-in ability to *predict what happens next* in its environment — to answer "if things are like this, and I do that, what will the world do back?" It is a little simulator of your surroundings, carried around in your head, running one step ahead of you.

[[note: metaphor || A world model is like the trajectory you feel in your arm before you throw a ball. You do not compute physics equations; you have a learned sense of where the ball will land, and that sense lets you aim before you release. An agent with a world model has that same "I know roughly what will happen" feeling about its own environment.]]

## A terminal is a world an agent can predict

To carry this into computing, we need to remember where a coding agent actually lives. In an [earlier chapter](what-is-a-terminal.html) we met the **terminal** — the text-only window where you type commands like `ls` (list the files here) or `python test.py` (run this program) and the computer types text back. A serious coding agent does its whole job here: it types a command, reads the reply, decides the next command, and repeats, sometimes for dozens of steps, until the task is done. We call such a thing a **terminal agent** — an agent that solves tasks by typing shell commands over many steps.

So what would a world model *of the terminal* look like? Simple: given the commands the agent has typed so far, predict the text the terminal will print back. If the agent is about to type `ls`, a good world model already half-expects the list of file names that will appear. If it is about to run the tests, it has a hunch about whether they will pass or throw a red error. The "world" here is the computer, and predicting it means predicting its replies.

## Blind trial-and-error versus a planning agent

Why would this hunch be worth anything? Picture two agents solving the same task, and the difference becomes obvious.

The first agent has *no* world model. It is not stupid — it can type good commands — but it has no sense of what any command will do until it actually runs it. So it works blind: type something, see what happens, react; type something else, see what happens, react. When it wanders into a dead end (a command that deletes the wrong file, a path that leads nowhere useful) it only discovers the mistake *after* making it, and has to back out and try again. It is a traveler in a strange city with no map, learning every street by walking down it.

The second agent has a world model. Before it commits to a command, it can quietly ask itself "and then what?" and get a decent answer. It can look a step ahead, notice that one path leads into a wall, and choose a different command instead. It still has to actually run things — the hunch is not perfect — but it acts *deliberately* rather than blindly. It is the traveler who has studied the map: still walking the real streets, but rarely surprised by them.

[[fig: A hand-drawn two-panel comparison titled "blind vs planning". [[note: example || Say the task is "make the test pass," and the agent is considering `rm test.py` (delete the test file). A blind agent might run it and only then realize it has thrown away the very thing that defines success. An agent with a world model predicts "this command removes the test — then there is nothing left to pass" and never types it. Same knowledge you have as a person who understands what a command does *before* pressing enter.]]

That last line is the whole point. A person who knows what a command will do before running it is calmer, faster, and less likely to break things. A world model is how we give an agent that same knowing-in-advance.

[[note: aha || An agent without a world model can only *react* to the computer. An agent with one can *anticipate* it — and anticipation is what lets you plan instead of grope.]]

## Where a world model usually comes from — and the tease

Here is the catch, and it is the reason our third project is interesting. A good world model is not free in the ordinary way of thinking. Normally, if you wanted an agent to predict a terminal's replies well, you would treat that as a whole separate skill to be trained on its own — more data, more compute, another job stacked on top of learning to act. Two lessons for the price of one, at twice the cost. That is the obvious path, and it is expensive. [[sn: This is a general pattern in machine learning: every extra capability you want usually means an extra training objective, extra data, and extra compute. Getting a genuinely useful second skill for almost no additional cost is unusual — which is exactly why the ECHO result is worth a chapter.]]

The project we turn to next — a replication of a method called **ECHO** — refuses that bargain. Its claim, sitting right there in the title of the paper it comes from, is that a terminal agent can pick up a world model **for free** — as a near-costless side effect of the very training that teaches it to act. [[sn: "ECHO" comes from the paper's phrasing, "Terminal Agents Learn World Models for Free." We are replicating the idea, not the exact leaderboard; the honest scientific claim is a controlled head-to-head, which we will set up carefully in the next chapter.]] No second data collection, no second heavy training run, almost no extra time on the machine. If that sounds too good, good — the *how* is the surprise, and it is where we go next.
